## Concerns (intersection of both waves)

Both waves independently surfaced the same non-blocking items. All are
**deferred to v3** per the v2 spec scope.

1. **P2-15** — `cooldownUntil` is still armed before the inventory read
   in `applySavedSetup(isAutomatic: true)` (`ScreenShifterModel.swift:300-322`).
   If the inventory read throws, the next legitimate automatic trigger
   is blocked for ~3 s. Audit P2-15.
2. **P2-6** — `displayModeDescriptor(for:)` still classifies HiDPI via
   `pixelWidth > logicalWidth || pixelHeight > logicalHeight`
   (`SystemDisplayInventory.swift:60`). Stretched non-HiDPI modes
   (e.g. 2880×1080 / 1920×1080) are misclassified. Audit P2-6.
3. **P2-13** — `ScreenShifterModel` is still ~530 lines; v3 should split
   `automationPaused` / `keepExternalDisplayAwake` / `launchAtLoginEnabled`
   into a `SettingsStore` and the capture state into a `CaptureCoordinator`.
4. **P2-17** — `setLaunchAtLogin` discards the underlying `NSError`; the
   typed `ModelError.launchAtLoginFailed(reason:)` carries only the
   human direction.
5. **Nits** — `@preconcurrency import AppKit`, `Picker("Built-in display",
   selection: .constant(...))`, `SparkleUpdaterDelegate.appcastURLString`
   visibility, `displayModeDescriptor(for:)` as free function,
   `scheduledAutomation` deinit cancel, `UserDefaultsProfileStore.suiteName`
   flatMap.

Wave 1 also flagged:
6. **Nit** — `LocalLogStoreTests.testRotatesWhenFileExceedsMaxBytes` does
   not clean up its temp file. Trivial follow-up.
7. **Nit** — `ModelError.modeUnavailable` is defined but not currently
   surfaced by `applySavedSetup`; prune or wire in v3.
8. **Nit** — optimistic sleep assertion in `init` holds until the first
   `refresh()` even if the laptop currently has no external display; the
   first `refresh()` releases it. Window is sub-second on a normal Mac.

Wave 2 also flagged:
9. **Nit** — `prepareCapture` and `confirmCapture` left as no-op stubs on
   the model (`ScreenShifterModel.swift:198-202`, `:248-251`) so the public
   type signature is preserved. Reasonable trade-off; v3 can drop them if
   nothing references them.

## Note on `Foundation preflight` failure reported by Wave 2

Wave 2's report mentioned a `PROJECT_PREFLIGHT_*=fail` reproduction
without `--profile personal`. That is a known preflight-script bug
(embedded `foundation-doctor.sh` call drops the profile flag, so the
doctor runs against an empty profile env) — see the agent-memory entry
**"Foundation check-project-preflight.sh needs explicit --profile"** from
2026-08-08. It is **not a v2 regression**: running preflight with the
correct flag produces an all-green result on HEAD. The
`check-secrets.sh` gate (the only Foundation check that blocks a release
tag today) is `pass`.
